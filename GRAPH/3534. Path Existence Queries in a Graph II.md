# 3534. Path Existence Queries in a Graph II

**Difficulty:** 🔴 Hard

**Topic:** Sorting, Binary Search, Binary Lifting, Graphs, Greedy

---

# Problem Statement

You are given:

* `n` nodes labeled from `0` to `n-1`
* An array `nums`, where `nums[i]` is the value of node `i`
* An integer `maxDiff`

An undirected edge exists between nodes `i` and `j` if:

```text
|nums[i] - nums[j]| <= maxDiff
```

For each query `[u, v]`, return the **minimum number of edges** required to travel from node `u` to node `v`.

If no path exists, return `-1`.

> The graph is **unweighted**, so every edge has a cost of **1**.

---

# Example

### Input

```python
nums = [5,3,1,9,10]
maxDiff = 2

queries = [
    [0,1],
    [0,2],
    [2,3],
    [4,3]
]
```

### Output

```python
[1,2,-1,1]
```

---

# Intuition

At first glance, the graph seems impossible to build.

For every pair of nodes we need to check:

```text
|nums[i] - nums[j]| <= maxDiff
```

That would require

```text
O(n²)
```

edges, which is impossible for

```text
n = 100000
```

The trick is to observe something important.

> **The edge rule depends only on the values, not on the original indices.**

So instead of thinking about node numbers, think about the numbers in sorted order.

---

# Key Observation

Suppose

```text
nums = [5,3,1,9,10]
```

After sorting:

```text
Value : 1  3  5  9 10
Index : 2  1  0  3  4
```

Now every node only connects to values within `maxDiff`.

Nearby values in sorted order become nearby nodes in the graph.

Large gaps split the graph into different connected components.

Example:

```text
1 -- 3 -- 5      9 --10
```

Gap:

```text
9 - 5 = 4 > maxDiff
```

So there is **no possible path** between the two groups.

---

# Approach

### Step 1 — Sort the nodes

Store

```python
(value, original_index)
```

and sort by value.

Also create

```python
pos[original_index]
```

which tells us where each node appears in sorted order.

---

### Step 2 — Find Connected Components

Traverse the sorted values.

Whenever

```text
values[i] - values[i-1] > maxDiff
```

start a new component.

Example

```text
Values

1 3 5 | 9 10
```

becomes

```text
Component 0
Component 0
Component 0
Component 1
Component 1
```

If two queried nodes belong to different components:

```text
Answer = -1
```

---

### Step 3 — Sliding Window

For every sorted position `i`, find the **furthest position reachable using one edge**.

Example

```text
Values

1 2 4 5 8
```

Suppose

```text
maxDiff = 3
```

From value

```text
1
```

we can reach

```text
2
4
```

but not

```text
5
```

So

```text
next[0] = 2
```

Use two pointers to compute every `next[i]` in **O(n)**.

---

### Step 4 — Binary Lifting

Imagine

```text
next =
[3,4,5,6,...]
```

Instead of moving one jump at a time,

Binary Lifting lets us jump

```text
1 jump
2 jumps
4 jumps
8 jumps
...
```

This allows answering each query in

```text
O(log n)
```

instead of

```text
O(n)
```

---

# Python Solution

```python
from typing import List

class Solution:
    def pathExistenceQueries(
        self,
        n: int,
        nums: List[int],
        maxDiff: int,
        queries: List[List[int]]
    ) -> List[int]:

        # Sort by value
        arr = sorted((val, idx) for idx, val in enumerate(nums))

        values = [v for v, _ in arr]

        # original index -> sorted position
        pos = [0] * n
        for i, (_, idx) in enumerate(arr):
            pos[idx] = i

        # Connected component id
        comp = [0] * n
        cid = 0

        for i in range(1, n):
            if values[i] - values[i - 1] > maxDiff:
                cid += 1
            comp[i] = cid

        # next[i] = furthest node reachable in one edge
        nxt = [0] * n
        r = 0

        for i in range(n):
            while r + 1 < n and values[r + 1] - values[i] <= maxDiff:
                r += 1
            nxt[i] = r

        # Binary Lifting table
        LOG = n.bit_length()
        up = [nxt]

        for _ in range(1, LOG):
            prev = up[-1]
            cur = [0] * n
            for i in range(n):
                cur[i] = prev[prev[i]]
            up.append(cur)

        ans = []

        for u, v in queries:

            l = pos[u]
            r = pos[v]

            if l > r:
                l, r = r, l

            if comp[l] != comp[r]:
                ans.append(-1)
                continue

            if l == r:
                ans.append(0)
                continue

            jumps = 0
            cur = l

            for k in range(LOG - 1, -1, -1):
                if up[k][cur] < r:
                    cur = up[k][cur]
                    jumps += 1 << k

            ans.append(jumps + 1)

        return ans
```

# Complexity Analysis

| Metric | Complexity           |
| ------ | -------------------- |
| Time   | **O((n + q) log n)** |
| Space  | **O(n log n)**       |

Where:

* `n` = number of nodes
* `q` = number of queries

---

# Why This Works

* Sorting transforms the graph into a structure based on values.
* Large value gaps naturally separate connected components.
* Sliding Window finds the furthest node reachable in one edge in linear time.
* Binary Lifting efficiently computes the minimum number of jumps between two positions.
* Each query is answered in **O(log n)** instead of performing BFS.

---

# Key Takeaways

* If graph connectivity depends **only on node values**, consider **sorting** instead of constructing the graph.
* Large gaps in sorted values can identify **connected components** without DFS/BFS.
* **Sliding Window** is useful for finding the furthest reachable element under a value constraint.
* **Binary Lifting** is not only for trees—it can also optimize repeated jump operations in arrays and graphs.
