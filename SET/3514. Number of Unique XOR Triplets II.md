# 3514. Number of Unique XOR Triplets II

**Difficulty:** 🟡 Medium

**Topics:** Bit Manipulation, Hash Set, XOR

---

# Problem Statement

You are given an integer array `nums`.

A **XOR triplet** is defined as:

```
nums[i] XOR nums[j] XOR nums[k]
```

where:

```
i <= j <= k
```

Return the number of **unique XOR triplet values** that can be formed from all possible triplets.

---

# Approach

Instead of checking every possible triplet, we can reduce the problem using XOR properties.

### Key Observation

Any triplet XOR can be written as:

```
(a XOR b) XOR c
```

So the algorithm works in two stages:

1. Compute every unique XOR value of two different elements.
2. XOR each pair result with every element in the array.

The final set contains all unique triplet XOR values.

---

# Idea

### Step 1

Generate every unique XOR of two numbers.

```
pair = nums[i] XOR nums[j]
```

Store them in a set to remove duplicates.

### Step 2

For every unique pair XOR:

```
triplet = pair XOR nums[k]
```

Store the result in another set.

Finally, return the size of the triplet set.

---

### Input

```python
nums = [6,7,8,9]
```

Using pair XOR = **1**

```

1 ^ 7 = 6
1 ^ 8 = 9

```

Triplets so far:

```

```

Using pair XOR = **14**


No new values.

Using pair XOR = **15**

```

```

Still no new values.

Final unique XOR triplets:

```
{6,7,8,9}
```

Answer:

```
4
```

# Python Solution

```python
class Solution:
    def uniqueXorTriplets(self, nums):
        n = len(nums)

        if n == 1:
            return 1

        pairs = set()

        # Generate unique XORs of every pair
        for i in range(n):
            for j in range(i + 1, n):
                pairs.add(nums[i] ^ nums[j])

        triplets = set()

        # XOR every pair result with each element
        for pair in pairs:
            for num in nums:
                triplets.add(pair ^ num)

        return len(triplets)
```

# Complexity Analysis

| Metric | Complexity |
|---------|------------|
| Time Complexity | **O(n²)** |
| Space Complexity | **O(n²)** |

### Why?

- There are **O(n²)** possible pairs.
- Each unique pair XOR is stored in a set.
- Every pair XOR is combined with every element.

Overall complexity remains **O(n²)**.

---

# XOR Properties Used

### 1. Self XOR

```
x ^ x = 0
```

Example:

```
5 ^ 5 = 0
```

---

### 2. XOR with Zero

```
x ^ 0 = x
```

Example:

```
7 ^ 0 = 7
```

---

### 3. Commutative Property

```
a ^ b = b ^ a
```

Order does not matter.

---

### 4. Associative Property

```
(a ^ b) ^ c = a ^ (b ^ c)
```

This allows us to compute triplets as:

```
pair XOR num
```

instead of handling all three numbers together.

# Interview Takeaway

Whenever a problem asks for:

- XOR combinations
- Unique XOR values
- Pair or triplet XOR computations
- Reducing brute-force combinations

Think about:

- XOR properties (Associative & Commutative)
- Precomputing pair XORs
- Using a **Hash Set** to eliminate duplicates

These observations often reduce a brute-force **O(n³)** solution to **O(n²)**.
