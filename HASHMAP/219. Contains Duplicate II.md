# 219. Contains Duplicate II

**Difficulty:** 🟢 Easy

**Topic:** HashMap

---

## Problem Statement

Given an integer array `nums` and an integer `k`, return `True` if there are two **distinct indices** `i` and `j` such that:

* `nums[i] == nums[j]`
* `abs(i - j) <= k`

Otherwise, return `False`.

---

## Example 1

### Input

```python
nums = [1,2,3,1]
k = 3
```

### Output

```python
True
```

**Explanation:**

The duplicate value `1` appears at indices `0` and `3`.

```text
|3 - 0| = 3 <= k
```

Therefore, return `True`.

---

## Example 2

### Input

```python
nums = [1,0,1,1]
k = 1
```

### Output

```python
True
```

**Explanation:**

The duplicate value `1` appears at indices `2` and `3`.

```text
|3 - 2| = 1 <= k
```

Therefore, return `True`.

---

## Example 3

### Input

```python
nums = [1,2,3,1,2,3]
k = 2
```

### Output

```python
False
```

**Explanation:**

Although duplicates exist, every duplicate pair is farther than `k` indices apart.

---

# Approach

We use a **HashMap** to store the **most recent index** of every number.

For every element:

1. Check whether the number has been seen before.
2. If yes, calculate the distance between the current index and the previous index.
3. If the distance is less than or equal to `k`, return `True`.
4. Otherwise, update the stored index to the current index.
5. If no valid pair is found after traversing the array, return `False`.

---

## Why Store the Latest Index?

Suppose:

```python
nums = [1,0,1,1]
k = 1
```

If we keep the first occurrence of `1` (index `0`), then when we reach index `3`:

```text
3 - 0 = 3
```

This is greater than `k`.

However, if we update the HashMap every time we encounter a number:

```text
1 → index 2
```

Then,

```text
3 - 2 = 1
```

which satisfies the condition.

Therefore, we always store the **latest index**.

---

## Python Solution

```python
class Solution:
    def containsNearbyDuplicate(self, nums, k):
        hashmap = {}

        for i in range(len(nums)):
            num = nums[i]

            if num in hashmap:
                if i - hashmap[num] <= k:
                    return True

            hashmap[num] = i

        return False
```

---

## Dry Run

```python
nums = [1,2,3,1]
k = 3
```

| Index | Number | HashMap           | Action                      |
| ----: | -----: | ----------------- | --------------------------- |
|     0 |      1 | `{}`              | Store `{1:0}`               |
|     1 |      2 | `{1:0}`           | Store `{1:0, 2:1}`          |
|     2 |      3 | `{1:0, 2:1}`      | Store `{1:0, 2:1, 3:2}`     |
|     3 |      1 | `{1:0, 2:1, 3:2}` | `3 - 0 = 3` → Return `True` |

---

## Complexity Analysis

| Metric | Complexity |
| ------ | ---------- |
| Time   | **O(n)**   |
| Space  | **O(n)**   |

### Why?

* We traverse the array only once.
* HashMap lookup and insertion take **O(1)** on average.
* In the worst case, every element is unique, so the HashMap stores all `n` elements.

---

## Key Takeaway

This problem is a variation of **Contains Duplicate**, where checking for duplicates alone is not enough.

Instead of only remembering **whether** a number has appeared, we also remember **where** it appeared.

Whenever a problem asks you to:

* Find duplicates
* Compare indices
* Check distance between occurrences
* Retrieve previously seen positions efficiently

consider storing:

```text
Value → Latest Index
```

using a **HashMap**.
