# 455. Assign Cookies

**Difficulty:** 🟢 Easy

**Topics:** Greedy, Sorting, Two Pointers

---

# Problem Statement

You are given:

- `g`, where `g[i]` is the **greed factor** of the `i`th child.
- `s`, where `s[j]` is the **size** of the `j`th cookie.

A child is content if they receive a cookie whose size is **greater than or equal to** their greed factor.

Each:

- Child can receive **at most one cookie**.
- Cookie can be assigned to **only one child**.

Return the **maximum number of content children**.

---

# Approach

We use a **Greedy** strategy along with **Sorting** and **Two Pointers**.

### Greedy Idea

- Give the **smallest available cookie** to the **least greedy child**.
- If the cookie is large enough, the child becomes content.
- Otherwise, try a larger cookie.

Sorting both arrays allows us to make the optimal choice at every step.

---

# Idea

### Step 1

Sort both arrays.

```
g.sort()
s.sort()
```

Example:

```
g = [2,3,1]
```

becomes

```
[1,2,3]
```

---

### Step 2

Use two pointers.

```
child = 0
cookie = 0
```

- `child` points to the current child.
- `cookie` points to the current cookie.

---

### Step 3

Compare the current cookie and greed.

If:

```
cookie >= greed
```

The child is satisfied.

```
child += 1
```

Move to the next cookie.

```
cookie += 1
```

---

If the cookie is too small,

```
cookie += 1
```

Try the next larger cookie.

---

### Step 4

Continue until all children or cookies are processed.

The number of satisfied children is:

```
child
```

---

# Python Solution

```python
class Solution:
    def findContentChildren(self, g: List[int], s: List[int]) -> int:

        g.sort()
        s.sort()

        child = 0
        cookie = 0

        while child < len(g) and cookie < len(s):

            if s[cookie] >= g[child]:
                child += 1

            cookie += 1

        return child
```

# Complexity Analysis

| Metric | Complexity |
|---------|------------|
| Time Complexity | **O(n log n + m log m)** |
| Space Complexity | **O(1)** *(excluding sorting space)* |

Where:

- `n` = Number of children
- `m` = Number of cookies

### Why?

- Sorting the children takes **O(n log n)**.
- Sorting the cookies takes **O(m log m)**.
- The two-pointer traversal is **O(n + m)**.

The sorting step dominates the overall complexity.

---

# Why the Greedy Approach Works

Giving a **large cookie** to a child with **small greed** unnecessarily wastes resources.

Instead:

- Satisfy the least greedy child using the smallest possible cookie.
- Save larger cookies for greedier children.

This greedy choice always leaves the greatest flexibility for the remaining assignments, ensuring the maximum number of content children.
