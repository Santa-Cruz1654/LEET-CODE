# 202. Happy Number

**Difficulty:** 🟢 Easy

**Topics:** Two Pointers, Fast & Slow Pointer, Cycle Detection, Math

---

# Problem Statement

A **happy number** is a number that eventually becomes `1` after repeatedly replacing the number with the **sum of the squares of its digits**.

For example:

```text
19
↓
1² + 9² = 82
↓
8² + 2² = 68
↓
6² + 8² = 100
↓
1² + 0² + 0² = 1
```

Since `19` eventually reaches `1`, it is a **happy number**.

If the process enters a cycle that does not contain `1`, the number is **not happy**.

---

# Approach

We can treat the sequence of numbers as a **linked list**.

For example:

```text
19 → 82 → 68 → 100 → 1
```

For an unhappy number, the sequence eventually enters a cycle.

For example, starting with `2`:

```text
2 → 4 → 16 → 37 → 58 → 89 → 145 → 42 → 20
                                            ↓
                                            4
```

So:

```text
4 → 16 → 37 → ... → 20 → 4
```

This is a cycle.

Therefore, we can use the same **Fast & Slow Pointer** technique used in Linked List Cycle problems.

---

# Idea

We use two pointers:

- `i` → slow pointer
- `j` → fast pointer

For every iteration:

### Slow pointer

Calculate the next number **once**:

```python
i = next_number(i)
```

### Fast pointer

Calculate the next number **twice**:

```python
j = next_number(j)
j = next_number(j)
```

Eventually:

```python
i == j
```

There are two possibilities:

### Case 1: They meet at `1`

```text
i == j == 1
```

The number is happy.

### Case 2: They meet somewhere else

```text
i == j != 1
```

They found a cycle that doesn't contain `1`.

The number is not happy.

---

# Dry Run

### Input

```python
n = 19
```

Sequence:

```text
19 → 82 → 68 → 100 → 1 → 1
```

Initially:

```text
i = 19
j = 19
```

### First iteration

Slow moves once:

```text
i = 82
```

Fast moves twice:

```text
j = 68
```

### Continue

Eventually:

```text
i = 1
j = 1
```

They meet at `1`.

Therefore:

```python

```

returns:

```text
True
```

# Dry Run for an Unhappy Number

### Input

```python
n = 2
```

The sequence is:

```text
2
↓
4
↓
16
↓
37
↓
58
↓
89
↓
145
↓
42
↓
20
↓
4
```

Notice:

```text
4 → 16 → 37 → ... → 20 → 4
```

A cycle exists.

The pointers eventually meet at a number other than `1`.

For example:

```text
i == j == 4
```

Therefore:

```python
i == 1
```

is `False`.

Answer:

```text
False
```

---

# Python Solution

```python
class Solution:
    def isHappy(self, n: int) -> bool:

        i = n
        j = n

        while True:

            # Slow pointer: move once
            i = sum(int(digit) ** 2 for digit in str(i))

            # Fast pointer: move twice
            j = sum(int(digit) ** 2 for digit in str(j))
            j = sum(int(digit) ** 2 for digit in str(j))

            if i == j:
                break

        return i == 1
```

---

# Understanding Your Code

This line:

```python
i = sum(int(digit) ** 2 for digit in str(i))
```

calculates the next number for the slow pointer.

For example:

```text
i = 19
```

Convert to string:

```python
str(19)
```

gives:

```text
"19"
```

Then:

```python
int('1') ** 2
+
int('9') ** 2
```

becomes:

```text
1² + 9²
= 1 + 81
= 82
```

So:

```text
19 → 82
```

---

For the fast pointer:

```python
j = sum(int(digit) ** 2 for digit in str(j))
j = sum(int(digit) ** 2 for digit in str(j))
```

The first line moves it once:

```text
19 → 82
```

The second line moves it again:

```text
82 → 68
```

So `j` moves **twice as fast** as `i`.

---

# Why `while True`?

We don't know in advance how many iterations are required.

We stop when:

```python
i == j
```

So:

```python
while True:
```

allows us to keep calculating until the two pointers meet.

Then:

```python
if i == j:
    break
```

stops the loop.

---

# Important Connection to Linked List Cycle II

This problem is a great example of recognizing a **pattern**.

In:

```text
142. Linked List Cycle II
```

we had:

```text
node → node → node → ...
```

and used:

```text
slow → 1 step
fast → 2 steps
```

Here we have:

```text
number → next number → next number → ...
```

For example:

```text
19 → 82 → 68 → 100 → 1
```

It's conceptually the same thing.

So we can reuse **Floyd's Cycle Detection**.

---

# Why Must a Cycle Eventually Occur?

The values don't keep growing forever.

Suppose `n` has many digits.

After calculating the sum of squared digits, the result becomes much smaller.

For a 32-bit integer, the sum of squares of its digits is at most:

```text
10 × 9² = 810
```

So eventually the sequence is confined to a relatively small set of values.

Therefore, it must either:

```text
reach 1
```

or:

```text
repeat a previous value → cycle
```

---

# Complexity Analysis

Let `d` be the number of digits involved in calculating the next value.

Each transformation takes:

```text
O(d)
```

The sequence reaches either `1` or a cycle after a bounded number of transformations for the given integer range.

For practical analysis of this problem:

| Metric | Complexity |
|---------|------------|
| Time Complexity | **O(log n)** |
| Space Complexity | **O(1)** |

The important part is that we don't store all previously seen numbers.

---

# Alternative Approach: Hash Set

Another common solution is to use a `set`:

```python
seen = set()

while n != 1:

    if n in seen:
        return False

    seen.add(n)

    n = sum(int(digit) ** 2 for digit in str(n))

return True
```

This is easier to understand initially, but it uses extra memory.

Your **Fast & Slow Pointer** solution is better when the interviewer asks for:

```text
O(1) extra space
```

# Interview Takeaway

This problem teaches an important pattern:

> **Cycle Detection isn't only for linked lists.**

Whenever you have a process like:

```text
value
  ↓
next value
  ↓
next value
  ↓
...
```

and the process can potentially repeat, think:

**Fast & Slow Pointers / Floyd's Cycle Detection**

The pattern is:

```python
slow = n
fast = n

while True:

    slow = next_value(slow)

    fast = next_value(fast)
    fast = next_value(fast)

    if slow == fast:
        break

return slow == 1
```

This is the same core idea as **142. Linked List Cycle II**, just applied to a sequence of numbers instead of linked-list nodes.
