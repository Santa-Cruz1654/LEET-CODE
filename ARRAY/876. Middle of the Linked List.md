# 876. Middle of the Linked List

**Difficulty:** 🟢 Easy

**Topics:** Linked List, Two Pointers

---

# Problem Statement

Given the `head` of a singly linked list, return the **middle node** of the linked list.

- If the list has **one middle node**, return it.
- If the list has **two middle nodes**, return the **second** middle node.

---

# Approach 1: Counting Nodes

First, count the total number of nodes in the linked list.

Then,

1. Compute the middle index.
2. Traverse the list again until reaching the middle node.
3. Return that node.

---

# Idea

### Step 1

Traverse the linked list and count the number of nodes.

```
count = total nodes
```

---

### Step 2

Find the middle index.

```
middle = count // 2
```

Using integer division automatically gives the second middle node for even-length lists.

---

### Step 3

Traverse from the head for `middle` steps.

Return the current node.

---

# Dry Run

### Input

```text
1 → 2 → 3 → 4 → 5
```

Count:

```
5
```

Middle index:

```
5 // 2 = 2
```

Move two steps:

```
1 → 2 → 3
```

Return:

```
3 → 4 → 5
```

---

### Even-Length Example

```text
1 → 2 → 3 → 4 → 5 → 6
```

Count:

```
6
```

Middle index:

```
6 // 2 = 3
```

Move three steps:

```
1 → 2 → 3 → 4
```

Return:

```
4 → 5 → 6
```

---

# Python Solution (Counting Method)

```python
class Solution:
    def middleNode(self, head):

        count = 0
        current = head

        while current:
            count += 1
            current = current.next

        middle = count // 2

        current = head

        for _ in range(middle):
            current = current.next

        return current
```

---

# Complexity Analysis

| Metric | Complexity |
|---------|------------|
| Time Complexity | **O(n)** |
| Space Complexity | **O(1)** |

### Why?

- First traversal counts the nodes.
- Second traversal reaches the middle.
- No extra data structures are used.

---

# Approach 2: Slow and Fast Pointer (Optimal)

We use two pointers:

- **Slow Pointer** → moves one node at a time.
- **Fast Pointer** → moves two nodes at a time.

When the fast pointer reaches the end, the slow pointer will be at the middle.

---

# Idea

Initialize:

```
slow = head
fast = head
```

Move the pointers:

```
slow = slow.next
fast = fast.next.next
```

Continue while:

```
fast and fast.next
```

Finally,

```
return slow
```

---

# Dry Run

### Input

```text
1 → 2 → 3 → 4 → 5
```

| Slow | Fast |
|------|------|
|1|1|
|2|3|
|3|5|

Fast reaches the end.

Return:

```
3
```

---

### Even-Length Example

```text
1 → 2 → 3 → 4 → 5 → 6
```

| Slow | Fast |
|------|------|
|1|1|
|2|3|
|3|5|
|4|None|

Return:

```
4
```

This automatically returns the **second middle node**.

---

# Python Solution (Slow & Fast Pointer)

```python
class Solution:
    def middleNode(self, head: Optional[ListNode]) -> Optional[ListNode]:

        slow = head
        fast = head

        while fast and fast.next:

            slow = slow.next
            fast = fast.next.next

        return slow
```

---

# Complexity Analysis

| Metric | Complexity |
|---------|------------|
| Time Complexity | **O(n)** |
| Space Complexity | **O(1)** |

### Why?

- Each node is visited at most once.
- Only two pointers are used.

---

# Which Approach is Better?

| Approach | Time | Space | Traversals |
|-----------|------|--------|------------|
| Counting Nodes | O(n) | O(1) | 2 |
| Slow & Fast Pointer | O(n) | O(1) | 1 ✅ |

The **Slow & Fast Pointer** approach is preferred because it finds the middle in a **single traversal**, making it the standard interview solution.

---

# Interview Takeaway

Whenever a Linked List problem asks for:

- Middle node
- Detecting cycles
- Finding the k-th node from the end
- Splitting a linked list
- Meeting point of pointers

Think of the **Slow & Fast Pointer (Tortoise and Hare)** technique.

It is one of the most common and important Linked List patterns in coding interviews.
