# 142. Linked List Cycle II

**Difficulty:** 🟡 Medium

**Topics:** Linked List, Two Pointers, Fast & Slow Pointer, Floyd's Cycle Detection

---

# Problem Statement

Given the `head` of a linked list, return the **node where the cycle begins**.

If there is no cycle, return:

```python
None
```

You must **not modify** the linked list.

---

# Approach

We use **Floyd's Cycle Detection Algorithm**, also known as the **Tortoise and Hare Algorithm**.

We use two pointers:

- `i` → slow pointer, moves **one step** at a time.
- `j` → fast pointer, moves **two steps** at a time.

There are two phases:

### Phase 1: Detect whether a cycle exists

Move:

```python
i = i.next
j = j.next.next
```

If there is a cycle, eventually:

```python
i == j
```

If `j` reaches `None`, there is no cycle.

---

### Phase 2: Find the Beginning of the Cycle

Once `i` and `j` meet:

1. Move `i` back to `head`.
2. Keep `j` at the meeting point.
3. Move both one step at a time.

```python
i = i.next
j = j.next
```

The point where they meet again is the **beginning of the cycle**.

---

# Understanding the Structure

Consider:

```text
3 → 2 → 0 → -4
    ↑         ↓
    └─────────┘
```

The cycle starts at:

```text
2
```

We can think of the list as:

```text
head
 ↓
3 → 2 → 0 → -4
    ↑         ↓
    └─────────┘
```

There are two parts:

```text
3
│
└──→ cycle begins at 2
```

and then the circular portion:

```text
2 → 0 → -4
↑         ↓
└─────────┘
```

---

# Phase 1: Detect the Cycle

Initialize:

```python
i = head
j = head
```

The slow pointer moves one step:

```python
i = i.next
```

The fast pointer moves two steps:

```python
j = j.next.next
```

Eventually, because they are inside the same cycle, they meet.

For example:

```text
        ┌─────────────┐
        ↓             │
3 → 2 → 0 → -4 ───────┘
        ↑
      cycle
```

The two pointers will eventually collide somewhere inside the cycle.

**Important:** The meeting point is usually **not the beginning of the cycle**.

### Input

```text
3 → 2 → 0 → -4
    ↑         ↓
    └─────────┘
```

Initial:

```text
i = 3

```

### Move 1

```text

```

### Move 2

```text

```

### Move 3

```text

```

They meet.

So:

```python

```

We know a cycle exists.

But `-4` is **not** the beginning of the cycle.

---

# Phase 2: Find the Cycle Beginning

Now reset the slow pointer:

```python
i = head
```

So:

```text
i = 3
j = -4
```

Now move both one step at a time.

### Step 1

```text
i = 2
j = 2
```

They meet at:

```text
2
```

Therefore:

```python
return i
```

The cycle begins at node `2`.

# Python Solution

```python
class Solution:
    def detectCycle(self, head: Optional[ListNode]) -> Optional[ListNode]:

        i = head
        j = head

        # Phase 1: Detect cycle
        while j and j.next:

            i = i.next
            j = j.next.next

            if i == j:
                break

        # No cycle
        if not j or not j.next:
            return None

        # Phase 2: Find cycle beginning
        i = head

        while i != j:

            i = i.next
            j = j.next

        return i
```

---

# Why Does Resetting `i` Work?

This is the important mathematical idea behind Floyd's algorithm.

Suppose:

```text
a = distance from head to cycle beginning
b = distance from cycle beginning to meeting point
c = remaining distance in the cycle
```

At the meeting point:

```text
Slow distance = a + b
```

Fast pointer travels twice as far:

```text
Fast distance = 2(a + b)
```

Because the fast pointer has completed some extra cycles:

```text
2(a + b) = a + b + cycle_length × k
```

Therefore:

```text
a + b = cycle_length × k
```

So:

```text
a = cycle_length × k - b
```

This means:

> The distance from the head to the cycle beginning is equal to the distance from the meeting point to the cycle beginning when moving around the cycle.

That's why we can:

```python
i = head
```

and then move both pointers at the same speed.

They will meet exactly at the **cycle beginning**.

# Example: No Cycle

Consider:

```text
1 → 2 → 3 → None
```

Eventually:

```python
j.next == None
```

The loop stops.

Then:

```python
if not j or not j.next:
    return None
```

So we correctly return:

```text
None
```

---

# Why `while j and j.next`?

We have:

```python
j = j.next.next
```

So we need to make sure that:

```text
j exists
j.next exists
```

before moving `j` two steps.

Therefore:

```python
while j and j.next:
```

prevents accessing `.next` on `None`.

---

# Important Detail: `i == j`

We are comparing:

```python
if i == j:
```

not:

```python
if i.val == j.val:
```

Why?

Because we need to know whether they are pointing to the **same node**, not whether two different nodes happen to contain the same value.

For example:

```text
1 → 2 → 3 → 2
```

Two nodes could potentially have the same value, but that doesn't mean they are the same node.

So:

```python
i == j
```

checks node identity.

# Complexity Analysis

| Metric | Complexity |
|---------|------------|
| Time Complexity | **O(n)** |
| Space Complexity | **O(1)** |

### Why?

The slow and fast pointers traverse the linked list without storing visited nodes.

We don't use:

```python
set()
```

or any additional data structure.

Therefore:

```text
Time  → O(n)
Space → O(1)
```

# Interview Takeaway

Whenever you see a linked-list problem involving:

- Cycle detection
- Cycle starting point
- Infinite traversal
- Detecting repeated nodes without extra memory

Think:

**Floyd's Cycle Detection / Slow & Fast Pointers**

The pattern to remember is:

```python
slow = head
fast = head

# Phase 1
while fast and fast.next:

    slow = slow.next
    fast = fast.next.next

    if slow == fast:
        break

# No cycle
if not fast or not fast.next:
    return None

# Phase 2
slow = head

while slow != fast:

    slow = slow.next
    fast = fast.next

return slow
```

The key insight is:

> **First make the slow and fast pointers meet inside the cycle. Then reset one pointer to the head and move both one step at a time; their next meeting point is the start of the cycle.**
